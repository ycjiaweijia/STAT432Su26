Appendix C — Python Virtual Environments with uv

A Python virtual environment is a project-specific Python installation plus a project-specific set of packages. It prevents one project from breaking another project when packages are installed or upgraded.

For this course, the recommended tool is uv.

uv is a Python package and project manager written in Rust. It can:

  • install and manage Python versions,
  • create virtual environments,
  • install packages,
  • manage pyproject.toml,
  • create and use lock files,
  • run commands inside the project environment.

You may still see pip, venv, and conda in Python tutorials. They are useful tools, but for this course uv is the default recommendation because it is fast, consistent, and works well with modern Python projects.

C.1 Package and Environment Tools

There are several common tools in the Python ecosystem.

Tool Main role
uv Project manager, package installer, virtual environment manager, Python version manager.
pip Traditional Python package installer.
venv Built-in Python virtual environment tool.
conda Environment and package manager, especially common in scientific computing.

pip and venv are standard Python tools. conda is common in data science and can install non-Python libraries. uv covers the workflow we need in this course and is the tool emphasized here.

NoteRecommendation

Use uv for this course unless you have a strong reason to use conda.

If you already use conda successfully, you do not need to remove it. Just avoid mixing tools inside the same environment unless you know why.

C.2 Installing uv

Install uv from the official instructions:

https://docs.astral.sh/uv/getting-started/installation/

After installation, check that it works:

uv --version

On Windows, you may need to restart VS Code or open a new terminal after installation.

C.3 Creating a Project Environment

In a project folder, create a virtual environment with:

uv venv

By default, this creates a folder named .venv.

The .venv folder contains the Python environment for the project. It should usually not be committed to Git.

To request a specific Python version:

uv venv --python 3.12

If that Python version is not installed, uv can usually download and manage it.

C.4 Activating the Environment

On Windows Command Prompt:

.venv\Scripts\activate

On Windows PowerShell:

.venv\Scripts\Activate.ps1

On macOS or Linux:

source .venv/bin/activate

After activation, your terminal prompt usually shows the environment name.

To deactivate:

deactivate
NoteActivation is optional with uv run

With uv, you can often avoid manual activation by using uv run.

For example:

uv run python
uv run quarto render

uv run runs the command inside the project environment.

C.5 Installing Packages

For this course, the main packages are:

  • numpy,
  • pandas,
  • matplotlib,
  • scikit-learn,
  • statsmodels,
  • jupyter,
  • ipykernel.

Install them with:

uv pip install numpy pandas matplotlib scikit-learn statsmodels jupyter ipykernel

This command installs packages into the current virtual environment.

If the environment is not activated, use:

uv pip install --python .venv numpy pandas matplotlib scikit-learn statsmodels jupyter ipykernel

In many project workflows, it is better to add dependencies to pyproject.toml:

uv add numpy pandas matplotlib scikit-learn statsmodels jupyter ipykernel

This records the dependencies as part of the project.

C.6 Project Files: pyproject.toml and uv.lock

Modern Python projects often use pyproject.toml to record project metadata and dependencies.

A simple dependency section may look like:

[project]
dependencies = [
    "numpy",
    "pandas",
    "matplotlib",
    "scikit-learn",
    "statsmodels",
    "jupyter",
    "ipykernel",
]

uv.lock records exact package versions. This helps rebuild the same environment later.

The usual files are:

  • pyproject.toml: project dependencies and settings;
  • uv.lock: exact locked package versions;
  • .venv/: local virtual environment folder.

Usually pyproject.toml and uv.lock are committed to Git. The .venv/ folder is not.

C.7 Syncing an Existing Project

If a project already has pyproject.toml and uv.lock, use:

uv sync

This creates or updates .venv so that it matches the lock file.

Then run Python commands with:

uv run python

or activate the environment and use python directly.

C.8 Running Jupyter with the Environment

VS Code can usually detect .venv automatically. In a notebook, click Select Kernel and choose the .venv environment.

If the environment does not appear, install and register an IPython kernel:

uv run python -m ipykernel install --user --name stats --display-name "Python (stats)"

Here stats is the kernel name. The display name is what you see in VS Code or Jupyter.

This is useful for Quarto documents that contain:

jupyter: stats

After registering the kernel, check available kernels with:

uv run jupyter kernelspec list

C.9 Common uv Commands

Create a virtual environment:

uv venv

Create a virtual environment with a specific Python version:

uv venv --python 3.12

Install packages into the environment:

uv pip install numpy pandas matplotlib scikit-learn

Add dependencies to the project:

uv add numpy pandas matplotlib scikit-learn

Remove a dependency:

uv remove scikit-learn

Synchronize from pyproject.toml and uv.lock:

uv sync

Run a command inside the environment:

uv run python

Run Quarto inside the environment:

uv run quarto render

Show installed packages:

uv pip list

C.10 uv pip versus uv add

There are two common ways to install packages.

Use uv pip install for quick one-time installation:

uv pip install scikit-learn

Use uv add when the package should be recorded as a project dependency:

uv add scikit-learn

For course projects, uv add is usually better because it updates pyproject.toml and the lock file.

For quick experiments, uv pip install is fine.

C.11 How pip Fits In

pip is the traditional Python package installer.

The classic workflow is:

python -m venv .venv
.venv\Scripts\activate
pip install numpy pandas matplotlib scikit-learn

This still works. uv provides a faster and more project-oriented version of this workflow.

Many pip commands have a uv pip equivalent:

pip install scikit-learn
uv pip install scikit-learn

For this course, prefer the uv version.

C.12 How conda Fits In

conda is an environment and package manager often used in data science. It is especially useful when a project needs non-Python system libraries or packages that are easier to install from conda-forge.

A typical conda workflow is:

conda create --name stats python=3.12
conda activate stats
conda install -c conda-forge numpy pandas matplotlib scikit-learn jupyter

This is a reasonable alternative if your machine already uses conda.

However, avoid mixing conda, pip, and uv casually inside the same environment. Pick one main tool for a project.

CautionDo not mix tools unnecessarily

If a project is managed by uv, install project packages with uv.

If a project is managed by conda, install packages with conda when possible.

Mixing tools can make environments harder to reproduce.

C.13 Reproducibility

The old pip workflow often used:

pip freeze > requirements.txt
pip install -r requirements.txt

This can work, but it is not ideal for project management.

With uv, the preferred reproducibility workflow is:

uv add numpy pandas matplotlib scikit-learn statsmodels jupyter ipykernel
uv lock

Then another user can recreate the environment with:

uv sync

This uses pyproject.toml and uv.lock instead of a manually maintained requirements.txt.

C.14 Recommended Course Setup

For a new course project:

  1. Open the project folder in VS Code.
  2. Create the environment:
uv venv --python 3.12
  1. Add the course packages:
uv add numpy pandas matplotlib scikit-learn statsmodels jupyter ipykernel
  1. Register the Jupyter kernel if needed:
uv run python -m ipykernel install --user --name stats --display-name "Python (stats)"
  1. In VS Code, select the .venv or "Python (stats)" kernel.

After this setup, Python, Jupyter, Quarto, and sklearn should use the same project environment.
